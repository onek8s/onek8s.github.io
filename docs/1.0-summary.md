# 1.0 Summary

The whole design in a few pages, for the reader who has to decide or sign off and will not read the rest: what the
platform is, the bets it stands on, the decisions that shape it, what runs today, what still needs a person, and what
it costs. Every line links to the section that holds the detail; this page adds nothing the sections do not say.
It is also its own PDF: [onek8s-design-summary.pdf](https://onek8s.github.io/onek8s-design-summary.pdf).

## What it is

**One Kubernetes platform, one application contract for every cloud – built on Azure (AKS) first.** Applications,
their manifests and the platform's in-cluster configuration use only open standards – Kubernetes, OCI, Flux, the
Gateway API, External Secrets, OIDC workload identity, OpenTelemetry – and data lives in PaaS services that every major
cloud offers over the same protocol. The contract is portable today ([section 1.3](1.3-open-standards-and-portability.md),
R26); the platform under it is an AKS platform that leans on what Azure manages, and a second cloud is another
implementation of it.

![Overview](../images/1.1-overview.svg)

The landing zone is hub-and-spoke with **one hub and one Azure Firewall Premium per exposure** – internal and external
workloads never share a subscription, a cluster, a hub or a route ([D52](7.2-decisions.md#decision-matrix),
[D53](7.2-decisions.md#decision-matrix), [section 1.1](1.1-overview.md)). Inside a cluster, countries are **isolation
zones**: their own nodes, subnets, route tables, Key Vault and policies, with the hub Firewall between them
([section 2.1](2.1-network-layout.md), [section 2.4](2.4-allowed-and-blocked-flows.md)). Inside a zone, every
application has its own namespace with default-deny policies, its own workload identity and its own share of the zone's
vault ([section 2.5](2.5-workload-identity-and-secrets.md), [section 2.6](2.6-application-multi-tenancy.md)).

![Cluster topology](../images/3.1-cluster-topology.svg)

The fleet is **fourteen clusters, twenty with the optional stateful clusters**: per exposure and environment (dev,
acc, prd) two or three zonal **stateless cells** – each a cluster in one availability zone that can be drained,
upgraded or rebuilt at any time – and, only when a workload needs it, one zone-redundant **stateful cluster** in the
Internet-less backend network ([section 3.1](3.1-cluster-types-stateless-and-stateful.md),
[section 3.2](3.2-environments.md)). External applications run in every cell behind Traffic Manager's DNS affinity;
internal applications run in one home cell each and are migrated between cells. Everything in a cluster comes from
one Git repository, delivered by Flux to the cells and by a pipeline to the stateful cluster
([section 3.3](3.3-keeping-clusters-in-sync.md)); releases and cluster upgrades move through the cells one at a time,
behind the cell router ([section 3.4](3.4-zero-downtime-application-upgrades.md),
[section 3.5](3.5-zero-downtime-cluster-upgrades.md)).

![AI-driven day 2 operations](../images/6.1-ai-operations.svg)

Day-2 operations are run by **agents that observe with read-only identities and change the platform only by pull
request**, behind a deterministic merge gate that humans own ([section 6.1](6.1-ai-driven-day-2-operations.md)).
Telemetry goes to one Grafana Cloud stack per environment through Private Link ([section 6.2](6.2-observability-with-grafana-cloud.md));
only persistent data is backed up, immutably, into the paired region, and clusters are rebuilt from IaC and Git
([section 6.3](6.3-backup-and-region-recovery.md)).

## What is meant to hold

The bets the design spends its complexity on and nowhere else ([section 7.4](7.4-outlook-2030-and-the-options-kept-open.md#what-is-meant-to-hold)):

1. **The application contract is open standards only** – an application written to it in 2026 deploys unchanged in 2030.
2. **Clusters are cattle, cells are the unit of change** – every cluster-level change is a rebuild behind the router, not a migration.
3. **Isolation zones are the blast-radius unit inside a cell**, and can become their own cells later.
4. **Git is the only write path**, for humans and agents alike.
5. **Data lives in managed services**; the stateful cluster is the last option and does not exist until needed.
6. **Private by default**: no public endpoint but the external zones' gateways and the firewall's own address.
7. **The platform operates itself through agents**, inside guardrails humans own.

A feature is added only when something names it, the cloud manages it, it is a per-cell switch, applications do not
notice, and the way out is written before the way in ([D64](7.2-decisions.md#decision-matrix)); everything left out
today is in the [options kept open](7.4-outlook-2030-and-the-options-kept-open.md#the-options-kept-open) with its
trigger.

the reasons.

## Built today, and the target

The design follows the implementation where the two differ ([section 7.1](7.1-implementation-project-and-acceptance-testing.md)).

| Built today (the dev lab, build tenant) | Target |
|---|---|
| One internal environment in germanywestcentral: two cells, az3 the default pod-subnet cell and az2 the deprecated overlay kept for the comparison; a firewall VM enforces the designed Firewall Policies | Internal and external exposures with a real Azure Firewall per hub; dev, acc and prd |
| Private API servers, no public endpoint on any platform service, customer-managed keys, Azure Policy with most custom rules in deny | Every rule in deny before acceptance; VNet integration if Azure allows it with VNet encryption (H14) |
| Zones, gateways (Traefik), External Secrets per zone, workload identity, ABAC, OpenCost, Alloy from Fleet Management; the example application in both cells | Grafana Cloud over Private Link, SLO gates, synthetic monitoring |
| Two agents run by hand: egress rules proposed from the Firewall's denials, traffic flow pages generated from Git | Every agent on its own identity and schedule, the merge gate in front of prd |
| Flux from Git, every cell following `main` | One signed artifact per release, one tag per cell, placement as its own artifact |
| No stateful cluster, no backups, no Traffic Manager (no external zone in the lab) | Built with the first stateful exception; immutable backups in the paired region; active-active external cells |

The verifications still open are the capability matrix's rows marked "No"
([section 7.2](7.2-decisions.md#azure-capability-and-verification-matrix)), and the backlog of
[section 7.1](7.1-implementation-project-and-acceptance-testing.md#backlog-in-priority-order) is the order of the work.

## What still needs a person

The design assumes a default for each and is built on it; the named role confirms or overrules it before the
[connection readiness gate](7.1-implementation-project-and-acceptance-testing.md#connection-readiness-gate)
([the full table](7.2-decisions.md#human-sign-offs-still-needed)).

| Who | Sign-offs |
|---|---|
| Security team | A WAF or none for the external zones, and the FQDN catalogue (H03); the preview risk of Key Vault ABAC, the platform vault layout, HSM keys and rotation, backup subscription ownership (H07); the build tenant (H11, with the landing zone owners); VNet integration against VNet encryption (H14) and the cells' egress model (H15), both with the platform architect |
| Platform owner | The budget: three cells in prd, everything twice per exposure, a second Firewall, DDoS protection, standby connectivity (H05); the 3-week slow update speed (H06); community External Secrets Operator (H08); the policy engine in a second cloud (H12) |
| Business, application owners | Availability, failover and recovery targets, RPO and RTO (H04) |
| Network team | The platform's prefixes in the corporate IPAM (H02) |
| DNS team | The parent domain and the validation zone (H09) |
| Privacy, legal, compliance | Personal data in logs, the Grafana Cloud region, the model provider (H10); DORA, NIS2, a European exit, the CLOUD Act (H13) |

Answered already: H01 (country separation inside a cluster is enough, security 2026-10-14) and H16 (pods separated by
the Firewall, not Cilium alone, D76). The features a person still has to weigh beyond these are in
[section 7.3](7.3-open-questions.md).

## What it costs

The structure is fixed; the numbers are measured in acceptance and are the platform owner's sign-off (H05,
[section 3.2](3.2-environments.md#cost-and-capacity-model)).

- **Fixed per cell**: the system pool, the gateways and their load balancers, private endpoints, the hub peering, the
  Standard tier – paid per cell and exposure, which is why the third cell in prd costs only its fixed part.
- **Fixed per environment**: the hub share (a Firewall Premium per exposure, about 1,300 USD a month list each), Key
  Vaults, the registry (Premium only in prd), Traffic Manager, backups, the Grafana Cloud stack, Log Analytics.
- **Variable**: the zone nodes on load (on-demand and spot, amd64 and arm64, chosen per application), PaaS, telemetry
  volume, Firewall data processing, ACNS only in the cells that turn it on.

Capacity is N+1 per environment: with `k` cells every cell can carry `1/(k-1)` of the environment on top of its own
share, on on-demand capacity alone.
