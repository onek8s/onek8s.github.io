# Decisions

This page is the decision log of the design: what was decided, which options were weighed, why, and what still
needs a named human. It replaces the long list of [open questions](open-questions.md) that reviewers
([Grok](https://github.com/onek8s/onek8s.github.io/issues/7), [ChatGPT](https://github.com/onek8s/onek8s.github.io/issues/8))
asked to be turned into a decision record. The sections of the design stay the specification; this page says
*why* they read as they do and which choices are still provisional.

**How to read the tables**

| Status | Meaning |
|---|---|
| **Decided** | Justified below, reflected in the sections, no human action needed. Re-opened only by a design pull request. |
| **Decided – confirm** | The design has chosen a default and is built on it, but the choice spends money, accepts a risk or binds another team, so a named role must sign it off ([human sign-offs](#human-sign-offs-still-needed)). |
| **Verify** | No decision to make; an assumption about Azure that the dev lab or acceptance ([section 17](17-implementation-project-and-acceptance-testing.md)) proves or disproves ([capability matrix](#azure-capability-and-verification-matrix)). |
| **Open** | Only a human can answer it (business targets, regulation, corporate IPAM). The design states the default it assumes meanwhile. |

**Criteria** used to justify a decision, in the order the platform weighs them when they conflict:

| Code | Criterion |
|---|---|
| **Sec** | Security: least privilege, smaller blast radius, defence in depth |
| **Auto** | Maximum automation: no manual steps, no human in loops that must react in minutes |
| **Std** | Industry standard, or the Azure standard offering that AKS manages and upgrades |
| **Simple** | Fewer moving parts to run, patch and reason about |
| **Cost** | Lower steady-state or failure-mode cost |
| **Port** | Portability: open standards, the same platform in another cloud ([section 21](21-open-standards-and-portability.md)) |

## Decision matrix

| # | Topic | Options weighed | Decision | Why | Status |
|---|---|---|---|---|---|
| D01 | Cluster granularity | (a) One cluster per cell with isolation zones inside; (b) one cluster per zone (or per country) | **(a) within one exposure** since [D52](#decision-matrix): the country zones of an exposure are address spaces, subnets, NSGs, UDRs, nodes, vaults and policies inside one cluster per cell ([section 2](02-network-layout.md)); internal and external are separate clusters | Cost, Simple: one control plane, one Flux, one gateway control plane per cell and exposure instead of one per zone. Sec is kept with three enforcement layers (NSG, Firewall, Cilium) and tested negatively; the security team accepts node pool + network as the boundary between countries (2026-10-14). (b) stays the documented escalation if a regulator demands a hard VNet boundary per country | Decided (security, 2026-10-14) |
| D02 | Address plan | (a) `/12` per environment, `/16` per country, `/17` per zone; (b) `/17` per country when the corporate plan cannot spare it | **(a)** assumed; the structure works one level smaller ([address plan](08-cluster-types-stateless-and-stateful.md#vnets-and-address-plan)) | Simple: one summarisable prefix per zone across all clusters keeps every Firewall rule stable. Only the size is the corporate IPAM's call | Open ([H02](#human-sign-offs-still-needed)) |
| D03 | Cluster DNS | (a) CoreDNS on the system pool, shared by all zones; (b) CoreDNS per zone; (c) NodeLocal DNS | **(a)** | Std, Simple: AKS manages CoreDNS; DNS is one of the few flows R5 allows between zones by design ([flow ③](05-allowed-and-blocked-flows.md)); the FQDN policies' DNS proxy already sits in every pod's path. (c) needs host iptables rules that eBPF host routing forbids; (b) adds four deployments per cell for no isolation gain, because queries carry no application data | Decided |
| D04 | Web application firewall for external zones | (a) No WAF: Traffic Manager (DNS only), DDoS protection, NSG 443 only, gateway, Cilium ingress, application-level controls; (b) Application Gateway WAF v2 per external zone and cell in front of the gateway; (c) Front Door Premium WAF | **(a) at launch**, with (b) as the defined add-on ([section 8](08-cluster-types-stateless-and-stateful.md#external-zones-active-active-with-dns-affinity)) | (c) was rejected with Front Door (TLS must end in the cell, DNS affinity). (b) costs an Application Gateway per external zone and cell and terminates TLS once more; whether the OWASP rule set is required is the security team's call, not the platform's. The design keeps the layout so (b) can be switched on per zone without changing applications | Decided – confirm (security, [H03](#human-sign-offs-still-needed)) |
| D05 | Release cadence | (a) One fleet release train per environment per day; (b) continuous per-application releases; (c) in-cell progressive delivery | **(a)** with the emergency fast track; (c) only for strictly backwards-compatible back-end APIs ([section 11](11-zero-downtime-application-upgrades.md#releases-cell-by-cell)) | Auto: the train is a pipeline, not a meeting. Each cell costs a drain, rollout, test and return, so per-application trains would keep cells draining all day. The number of trains is tuned from the cell cycle time measured in acceptance | Decided |
| D06 | External client affinity | (a) Traffic Manager Subnet routing (affinity by client network); (b) cookie affinity in a layer-7 router; (c) no affinity | **(a)**, treated as an optimisation: the [compatibility rule](11-zero-downtime-application-upgrades.md) is the correctness guarantee | Simple, Sec: no stateful component in front of the cells, TLS ends in the cell. Clients behind shared resolvers or changing networks are covered by the compatibility rule; the share of such traffic is measured, not guessed (V07) | Decided |
| D07 | Internal applications on cell failure | (a) One home cell, alert-driven migration; (b) active-active in every cell like external zones | **(a)** ([section 8](08-cluster-types-stateless-and-stateful.md#internal-zones-one-home-cell-per-application-moved-by-migration)) | Cost, Simple: internal applications run once; the recovery time is alert + reconcile + DNS, minutes. Default target 15 minutes until the business sets one | Decided – confirm (business, [H04](#human-sign-offs-still-needed)) |
| D08 | Stateless cells in prd | (a) Two cells, each sized for 100 %; (b) three cells, each sized for 50 % headroom | **(b) in prd, two in dev and acc** ([section 9](09-environments.md)) | Sec (availability): with two cells an AZ loss *during* an upgrade leaves no redundancy. Cost: with NAP the third cell's steady cost is its fixed part (two system nodes, gateways, load balancers, private endpoints, peering); the pre-scale headroom per cell falls from 100 % to 50 %, and so does the quota. dev and acc rehearse with two because R11 needs at least two and the procedures are the same | Decided – confirm (platform owner, cost, [H05](#human-sign-offs-still-needed)) |
| D09 | Stateful cluster: Internet | (a) No Internet at all; (b) no Internet egress and no public endpoints, except allow-listed Microsoft control-plane endpoints that have no Private Link (Entra ID, Azure Policy) | **(b)**; R9 now says so ([requirements](requirements.md)) | Sec, Std: workload identity and the single policy engine both need these two endpoints; everything else uses Private Link. The allow-list is tested from the cluster and by Resource Graph ([section 17](17-implementation-project-and-acceptance-testing.md#requirement-and-isolation-tests)) | Decided |
| D10 | Stateful cluster: OS patching | (a) Node OS channel `Unmanaged` with kured and a private package mirror; (b) `SecurityPatch`; (c) `NodeImage` | **(b)**: AKS applies security-only patches to the existing nodes in place where it can and reimages only for kernel-level patches, inside the maintenance window ([section 12](12-zero-downtime-cluster-upgrades.md#stateful-cluster)) | Std, Simple, Auto: Microsoft-managed, no mirror and no reboot daemon to run in the Internet-less network. It meets "patch in place where possible, replace only when necessary" better than (a) because AKS decides per patch. **Re-check at build (V13)**: the network isolated cluster documentation of 2026-06 lists only `NodeImage` and `None` as supported channels; if AKS refuses `SecurityPatch` on outbound type `none`, (c) inside the same window is the plan | Decided; V13 may turn it into (c) |
| D11 | Node images in the stateless cells | (a) NAP's default (new nodes take the newest image); (b) pin `imageVersion` per cell in the zone `AKSNodeClass`, moved by the version pipeline | **(b)**, and the slow speed's steps shortened to 3 weeks (prd ≈ 9 weeks after release) ([update policy](12-zero-downtime-cluster-upgrades.md#update-policy)) | Sec (R12a): a node created during scale-out must run the cell's proven image. | D12 | Spot in prd | (a) Spot allowed in every zone, capped; (b) on-demand only in prd | **(a)**, cap `maxSpotShare: 0.5` per zone in `limits.yaml` ([section 4](04-node-pools.md#cpu-architecture-and-spot-chosen-by-the-application)) | Cost: the application opts in and declares it tolerates eviction; the on-demand `NodePool` alone is sized for N+1, so an eviction wave costs money, not availability | Decided |
