# 8.1 Release notes

The design is versioned, one minor version per pull request that changes it and a major version only when a human
says so, newest first; every version is tagged `v<version>` in every repository. The version is shown in the site's
header and on the covers of the [PDFs](https://github.com/onek8s/onek8s.github.io/blob/main/CONTRIBUTING.md#the-pdf-and-the-release-notes)
([how to add an entry](https://github.com/onek8s/onek8s.github.io/blob/main/CONTRIBUTING.md#the-pdf-and-the-release-notes)).

## v3.7 - 2026-10-20

- D73: a route table keeps only its own node subnet and pod slot inside the VNet - a zone's load balancer subnet, the
  rest of its slot, goes to the Firewall with the address space, so every table has the same five routes
  ([#107](https://github.com/onek8s/onek8s.github.io/pull/107)).

## v3.6 - 2026-10-20

- D73 again: the system pool's slot goes through the hub Firewall too - every node and pod subnet's route table has
  the same shape, a zone's own load balancer is reached through the Firewall, and the Kubernetes flows between the
  system pool and the zones are the Firewall's named rules (the API server's private endpoint alone keeps its /32
  system route), so the platform's own pods sit behind the same three layers as another zone
  ([#106](https://github.com/onek8s/onek8s.github.io/pull/106)).

## v3.5 - 2026-10-20

- D73 revised: a zone's route table sends the cell's address spaces to the hub Firewall with seven fixed routes, the
  zone's own and the system pool's slots kept in the VNet, instead of a route per other slot; an application reaches
  an application of another zone only through that zone's published name, with an application rule in its own rule
  file like any external API, which the Firewall proxies so the path is symmetric - never directly
  ([#105](https://github.com/onek8s/onek8s.github.io/pull/105)).

## v3.4 - 2026-10-20

- The built-in deployment safeguards initiative's warn-only member reports every pod a mutation changed; the
  platform's mutations change every application pod by design, so that member is disabled and the mutations and
  validations stay - a known limit of the policy add-on in section 2.7 ([#104](https://github.com/onek8s/onek8s.github.io/pull/104)).

## v3.3 - 2026-10-19

- Microsoft Defender is not used: the company's third-party security tool gives the posture score, image scanning and
  runtime alerts, and the landing zone assigns none of Defender's policies (D81) ([#103](https://github.com/onek8s/onek8s.github.io/pull/103)).
- In the build tenant every Azure Policy assignment moves from audit to deny as soon as it reports no non-compliant
  resource, and only the landing zone initiatives that govern what the platform runs on are assigned (D82) ([#103](https://github.com/onek8s/onek8s.github.io/pull/103)).
- Azure Policy requires Key Vault purge protection in production only (D83) ([#103](https://github.com/onek8s/onek8s.github.io/pull/103)).

## v3.2 - 2026-10-19

- Every picture of the design and summary PDFs is redrawn to fit the page width with readable labels (two or three
  columns instead of a wide row, tighter Mermaid spacing), and the redrawn pictures match the design again: Traefik
  with h2c in 4.1, KMS data encryption in 4.2, the three-week slow speed in 3.5, Azure first without implementation
  names in 1.3 and 5.2 ([#102](https://github.com/onek8s/onek8s.github.io/pull/102)).
- The sidebar and the Contents of the introduction mark which pages are in the design PDF and which have a PDF of
  their own; the `pdf:` key of each page in the navigation is the one source, which the PDF build and the check read
  ([#102](https://github.com/onek8s/onek8s.github.io/pull/102)).

## v3.1 - 2026-10-19

- The PDFs fit every picture on one page (the tall ones of 3.1, 3.2 and 3.5 scale down instead of being split over
  two or three pages) and keep a heading with what follows it; the design PDF drops from 97 to 94 pages
  ([#101](https://github.com/onek8s/onek8s.github.io/pull/101)).

## v3.0 - 2026-10-19

- The design PDF is cut under 100 pages: it holds sections 1.1 to 5.2 (the introduction and the summary have their
  own PDF), and the other clouds, sovereignty and exit move from 1.3 to the new page 7.5, outside the PDF
  ([#100](https://github.com/onek8s/onek8s.github.io/pull/100)).
- Kubernetes and AKS mechanics are links to the documentation instead of text: pod right-sizing (2.3), HTTP/2, App
  Routing and the service mesh (4.1), the stateful cluster's node OS and rollback (3.5), classic KMS (4.2), ABAC and
  the PaaS tenancy (2.5), Traffic Manager and DNS affinity (3.1)
  ([#100](https://github.com/onek8s/onek8s.github.io/pull/100)).
- The company firewall's delegation options move from 5.1 to 7.1, where the platform is connected, and the shared
  tier's fault table from 3.1 to 7.1's resilience tests
  ([#100](https://github.com/onek8s/onek8s.github.io/pull/100)).

## v2.2 - 2026-10-19

- Advanced Container Networking Services is removed (D80): the hub Firewall decides egress in every cell, page 5.1
  is gone and 5.2 and 5.3 are renumbered 5.1 and 5.2; FQDN filtering, Hubble and eBPF host routing are options kept
  open in 7.4 with measured triggers, and the dataplane baseline of 7.1 measures them
  ([#99](https://github.com/onek8s/onek8s.github.io/pull/99)).
- The PDFs leave parts 6 and 7 out until their review: the design PDF is parts 1 to 5, the reference PDF part 8
  ([#99](https://github.com/onek8s/onek8s.github.io/pull/99)).

## v2.1 - 2026-10-19

- The design describes the design only: the "built today" tables, the lab's cluster names and addresses, the
  implementation repositories, files, workflows and variables, the backlog of 7.1 and the "proven in the dev lab"
  column of the capability matrix are removed; the lab-bound decisions (D22, D31, D55-D58, D60, D62) are reworded
  as design decisions ([#98](https://github.com/onek8s/onek8s.github.io/pull/98)).
- The landing zone stays out of scope: section 5.1's firewall delegation is a table of the options with Microsoft's
  documentation, and section 5.2 describes the traffic flow pages without the first run's history
  ([#98](https://github.com/onek8s/onek8s.github.io/pull/98)).
- Pictures 2.1 and the 5.2 examples use example names instead of the lab's
  ([#98](https://github.com/onek8s/onek8s.github.io/pull/98)).

## v2.0 - 2026-10-19

- Azure CNI Overlay is removed: every cell is Azure CNI Pod Subnet with Cilium, and section 5.1 compares only who
  decides egress (D74, D61, D79) ([#97](https://github.com/onek8s/onek8s.github.io/pull/97)).
- AKS Automatic is removed with option E; D75 is retired ([#97](https://github.com/onek8s/onek8s.github.io/pull/97)).
- The dev lab is one cell, `aks-dev-int-stateless-az3` (Sweden's `int-se`); az1 and az2 are gone
  ([#97](https://github.com/onek8s/onek8s.github.io/pull/97)).
- Zone nodes are classic node pools with the cluster autoscaler; node auto provisioning stays out until it supports
  the pod subnet (a watch list row in 7.4) ([#97](https://github.com/onek8s/onek8s.github.io/pull/97)).
- Every repository is tagged with the design version (`v<version>`) by aks-terraform's `Design tags` workflow
  ([#97](https://github.com/onek8s/onek8s.github.io/pull/97)).

v1.0 to v1.15 are in the [v1.15 tag](https://github.com/onek8s/onek8s.github.io/tree/v1.15/docs/8.1-release-notes.md).
