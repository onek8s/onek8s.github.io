# 1.1 Overview

![Overview](../images/1.1-overview.svg)

Hub-and-spoke landing zone with **one hub per exposure** ([decision D53](7.2-decisions.md#decision-matrix)). The
**internal hub** holds the shared connectivity services of the internal exposure: Azure Firewall Premium (all egress
and east-west inspection), the VPN/ExpressRoute gateway, Private DNS and Bastion. The **external hub** has its own
Azure Firewall Premium and Private DNS links, but no gateway and no peering to the internal hub, so the clusters the
Internet reaches have no path to the corporate network at all. A separate **management VNet** hosts jump hosts and
CI/CD agents, is peered to both hubs (peering is not transitive, so it joins nothing) and is the only place the
Kubernetes API can be reached from.
**Internal and external workloads live in separate subscriptions and clusters** – `sub-aks-<env>-int` and
`sub-aks-<env>-ext` ([decision D52](7.2-decisions.md#decision-matrix)). Each **AKS spoke** contains one cluster of one
exposure, split into a control plane zone and the isolation zones of that exposure, one per country: `int-fi` and
`int-se` in an internal cluster, `ext-fi` and `ext-se` in an external one.
Every cluster of the fleet – stateless or stateful, internal or external – has this same inner layout; how the
clusters are placed in the frontend and backend networks is shown in [picture 3.1](3.1-cluster-types-stateless-and-stateful.md).
External zones receive Internet traffic on a public load balancer of the zone's gateway in every cell, with Azure
Traffic Manager choosing the cell by DNS;
internal zones are reached only from the corporate network through the internal hub's Firewall, directly at the zone's gateway in the cell that hosts the application (private DNS kept up to date by ExternalDNS). In both cases the traffic ends at the zone's gateway (AKS App Routing)
in a stateless cluster – the stateful cluster is never reached from outside the platform.
