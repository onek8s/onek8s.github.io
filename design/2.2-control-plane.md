# 2.2 Control plane

![Control plane](../images/2.2-control-plane.svg)

The API server is **private**: a private cluster over **Private Link**, its endpoint in the cell's system subnet,
no public endpoint ([decision D58](7.2-decisions.md#decision-matrix)). Its public FQDN resolves to the private
address (`private_dns_zone_mode = none`), so no AKS-managed private DNS zone has to be linked to every network: the
cells and the management network resolve through the hub firewall's DNS proxy. Admins (Entra ID + PIM, Azure RBAC for Kubernetes) and CI/CD reach it only from the
management network, through the hub Firewall's rule for it. The preferred form - **API Server VNet Integration**,
the API server projected as an internal load balancer into a dedicated delegated `snet-apiserver`, nodes talking to
it without a tunnel - is refused by Azure on the cells' encrypted networks with v4 and newer VM sizes; it stays open
as H14, and every cell keeps a slot for its subnet. The system node pool (tainted `CriticalAddonsOnly`, fixed node
count) runs only platform components.

- **No local accounts** (`--disable-local-accounts`): the certificate-based `clusterAdmin` credential would be a
  back door around Entra ID, PIM and the audit log. Every human, pipeline and agent signs in with Entra ID;
  break-glass is a PIM-activated Entra group, not a local credential. Azure Policy denies clusters with local
  accounts enabled.
- **Open: VNet integration and VNet encryption exclude each other** (H14): Azure refuses API Server VNet Integration on
  an encrypted virtual network with v4 and newer VM sizes, and the cells' networks are encrypted
  ([section 4.1](4.1-encryption-in-transit-and-tls.md)). Classic KMS with a private vault would need VNet integration;
  the cells use KMS data encryption, which reaches the private vault as a trusted service, so KMS does not decide
  the question ([section 4.2](4.2-encryption-at-rest-and-customer-managed-keys.md)).
- **No SSH to nodes** (`--ssh-access disabled` on every node pool): nodes are replaced, never logged into. Node-level
  diagnosis uses `kubectl debug node/…` or a kernel-level tracing tool, through break-glass only
  ([section 6.2](6.2-observability-with-grafana-cloud.md#security-detections-and-forensics)).
