## What it is

**One Kubernetes platform, one application contract for every cloud – built on Azure (AKS) first.** Applications,
their manifests and the platform's in-cluster configuration use only open standards – Kubernetes, OCI, Flux, the
Gateway API, External Secrets, OIDC workload identity, OpenTelemetry – and data lives in PaaS services that every major
cloud offers over the same protocol. The contract is portable today ([section 1.3](1.3-open-standards-and-portability.md),
R26); the platform under it is an AKS platform that leans on what Azure manages, and a second cloud is another
implementation of it.

![Overview](../images/1.1-overview.svg)

The landing zone is hub-and-spoke with **one hub and one Azure Firewall Premium per exposure** – internal and external
workloads never share a subscription, a cluster, a hub or a route ([D52](7.2-decisions.md#decision-matrix),
[D53](7.2-decisions.md#decision-matrix), [section 1.1](1.1-overview.md)). Inside a cluster, countries are **isolation
zones**: their own nodes, subnets, route tables, Key Vault and policies, with the hub Firewall between them
([section 2.1](2.1-network-layout.md), [section 2.4](2.4-allowed-and-blocked-flows.md)). Inside a zone, every
application has its own namespace with default-deny policies, its own workload identity and its own share of the zone's
vault ([section 2.5](2.5-workload-identity-and-secrets.md), [section 2.6](2.6-application-multi-tenancy.md)).

![Cluster topology](../images/3.1-cluster-topology.svg)

The fleet is **fourteen clusters, twenty with the optional stateful clusters**: per exposure and environment (dev,
acc, prd) two or three zonal **stateless cells** – each a cluster in one availability zone that can be drained,
upgraded or rebuilt at any time – and, only when a workload needs it, one zone-redundant **stateful cluster** in the
Internet-less backend network ([section 3.1](3.1-cluster-types-stateless-and-stateful.md),
[section 3.2](3.2-environments.md)). External applications run in every cell behind Traffic Manager's DNS affinity;
internal applications run in one home cell each and are migrated between cells. Everything in a cluster comes from
Git, delivered by Flux to the cells and by a pipeline to the stateful cluster
([section 3.3](3.3-keeping-clusters-in-sync.md)); releases and cluster upgrades move through the cells one at a time,
behind the cell router ([section 3.4](3.4-zero-downtime-application-upgrades.md),
[section 3.5](3.5-zero-downtime-cluster-upgrades.md)).

![AI-driven day 2 operations](../images/6.1-ai-operations.svg)

Day-2 operations are run by **agents that observe with read-only identities and change the platform only by pull
request**, behind a deterministic merge gate that humans own ([section 6.1](6.1-ai-driven-day-2-operations.md)).
Telemetry goes to one Grafana Cloud stack per environment through Private Link ([section 6.2](6.2-observability-with-grafana-cloud.md));
only persistent data is backed up, immutably, into the paired region, and clusters are rebuilt from IaC and Git
([section 6.3](6.3-backup-and-region-recovery.md)).

## The decisions that shape it

Of the entries in the [decision log](7.2-decisions.md), these decide the shape; the log has the options weighed and
the reasons.

| | Decision | Status |
|---|---|---|
| [D01](7.2-decisions.md#decision-matrix), [D52](7.2-decisions.md#decision-matrix) | One cluster per cell with the countries as isolation zones inside; internal and external in separate subscriptions and clusters | Decided (security, 2026-10-14) |
| [D53](7.2-decisions.md#decision-matrix) | A hub VNet and an Azure Firewall Premium per exposure, no route between them; the management VNet peered to both | Decided – confirm cost (H05) |
| [D74](7.2-decisions.md#decision-matrix), [D73](7.2-decisions.md#decision-matrix), [D79](7.2-decisions.md#decision-matrix) | One cell network, Azure CNI Pod Subnet with Cilium: every pod carries its zone's address, and every flow between two zones of a cell meets the hub Firewall (a route table per zone); classic node pools with the cluster autoscaler | Decided (2026-10-18, v2.0 2026-10-19) |
| [D61](7.2-decisions.md#decision-matrix), [D80](7.2-decisions.md#decision-matrix) | The hub Firewall decides egress per zone from per-application rules in every cell; ACNS (per-application FQDN policies, Hubble, eBPF host routing) is not used, each part an option kept open with a measured trigger | Decided; the company firewall's delegation open (H15) |
| [D60](7.2-decisions.md#decision-matrix), [D58](7.2-decisions.md#decision-matrix) | No public network access for any platform service; private API servers over Private Link (VNet integration refused on encrypted networks, H14) | Decided |
| [D08](7.2-decisions.md#decision-matrix), [D11](7.2-decisions.md#decision-matrix) | Three cells in prd, two in dev and acc; two update speeds with node images pinned per cell | Decided – confirm cost and R12a (H05, H06) |
| [D55](7.2-decisions.md#decision-matrix), [D69](7.2-decisions.md#decision-matrix)–[D71](7.2-decisions.md#decision-matrix) | Gateway API only, the implementation a per-cluster flag; HTTP/2 only and TLS 1.3 only in the whole gateway path – Traefik everywhere until App Routing can match it; Flux's GitHub webhook the one HTTP/1.1 exception ([D78](7.2-decisions.md#decision-matrix)) | Decided; refusing HTTP/1.1 at the edge still open (V29) |
| [D15](7.2-decisions.md#decision-matrix), [D49](7.2-decisions.md#decision-matrix)–[D51](7.2-decisions.md#decision-matrix) | Secrets only through External Secrets Operator, separated per namespace by Key Vault ABAC (preview); namespace roles from Entra ID groups with matching vault rights; tenants list nothing | Decided – confirm the preview risk (H07) |
| [D21](7.2-decisions.md#decision-matrix), [D22](7.2-decisions.md#decision-matrix) | Customer-managed HSM keys per control plane, per cluster's node disks and per zone's volumes; KMS data encryption (preview) because the private vault needs it | Decided – confirm (H07) |
| [D18](7.2-decisions.md#decision-matrix), [D67](7.2-decisions.md#decision-matrix) | The stateful cluster is built in every environment only with the first approved exception, on an LTS minor, with a storage agent that proposes and never deletes | Decided |
| [D25](7.2-decisions.md#decision-matrix), [D26](7.2-decisions.md#decision-matrix) | Agents start with a human on every tier above low and earn trust per agent and environment; platform and security own the limits together | Decided |
| [D66](7.2-decisions.md#decision-matrix) | The name OneK8s and the application contract as the promise, portability the last criterion | Decided |

The assumptions about Azure the design rests on are the
[capability matrix](7.2-decisions.md#azure-capability-and-verification-matrix), each with its fallback; the
[acceptance criteria](../requirements/0.3-acceptance-criteria.md) prove them.

## What still needs a person

The design assumes a default for each; the named role confirms or overrules it
([the full table](7.2-decisions.md#human-sign-offs-still-needed)).

| Who | Sign-offs |
|---|---|
| Security team | A WAF or none for the external zones, and the FQDN catalogue (H03); the preview risk of Key Vault ABAC, the platform vault layout, HSM keys and rotation, backup subscription ownership (H07); VNet integration against VNet encryption (H14) and the cells' egress model (H15), both with the platform architect |
| Platform owner | The budget: three cells in prd, everything twice per exposure, a second Firewall, DDoS protection, standby connectivity (H05); the 3-week slow update speed (H06); community External Secrets Operator (H08) |
| Business, application owners | Availability, failover and recovery targets, RPO and RTO (H04) |
| Network team | The platform's prefixes in the corporate IPAM (H02) |
| DNS team | The parent domain and the validation zone (H09) |
| Privacy, legal, compliance | Personal data in logs, the Grafana Cloud region, the model provider (H10) |

Answered already: H01 (country separation inside a cluster is enough, security 2026-10-14). The features a person still has to weigh beyond these are in
[section 7.3](7.3-open-questions.md).

## What it costs

The structure is fixed; the numbers are measured in acceptance and are the platform owner's sign-off (H05,
[section 3.2](3.2-environments.md#cost-and-capacity-model)).

- **Fixed per cell**: the system pool, the gateways and their load balancers, private endpoints, the hub peering, the
  Standard tier – paid per cell and exposure, which is why the third cell in prd costs only its fixed part.
- **Fixed per environment**: the hub share (a Firewall Premium per exposure, about 1,300 USD a month list each), Key
  Vaults, the registry (Premium only in prd), Traffic Manager, backups, the Grafana Cloud stack, Log Analytics.
- **Variable**: the zone nodes on load (on-demand and spot, amd64 and arm64, chosen per application), PaaS, telemetry
  volume, Firewall data processing.

Capacity is N+1 per environment: with `k` cells every cell can carry `1/(k-1)` of the environment on top of its own
share, on on-demand capacity alone.
