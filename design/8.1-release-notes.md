# 8.1 Release notes

**Requirements:** none - the version history of the design.

The design is versioned, one minor version per pull request that changes it and a major version only when a human
says so, newest first; every version is tagged `v<version>` in every repository. Only the current major version is
listed here: the older versions are in the Git tags, the last before v4.0 being
[`v3.8`](https://github.com/onek8s/onek8s.github.io/tree/v3.8). The version is shown in the site's
header and on the covers of the [PDFs](https://github.com/onek8s/onek8s.github.io/blob/main/CONTRIBUTING.md#the-pdf-and-the-release-notes)
([how to add an entry](https://github.com/onek8s/onek8s.github.io/blob/main/CONTRIBUTING.md#the-pdf-and-the-release-notes)).

## v4.13 - 2026-11-26

- App Routing's Istio serves every Gateway and Traefik is removed: the edge prefers HTTP/2 and TLS 1.3 but no longer refuses HTTP/1.1 and TLS 1.2 until App Routing can, the gateway keeps speaking h2c to the pods, and the `gateway-tls` policy and the zones' tenant lists go with Traefik (sections 1.0, 2.7, 3.3, 4.1) ([#130](https://github.com/onek8s/onek8s.github.io/pull/130)).
- DNS is App Routing's managed ExternalDNS and the route is the DNS switch: an internal application's own name has its route in the home cell alone, so no filter names a cell, and a migration moves the route, with a short gap in the name and the target tested under its per-cell name (sections 1.3, 1.5, 3.1, 3.3, 4.1) ([#130](https://github.com/onek8s/onek8s.github.io/pull/130)).
- Traffic Manager is removed: external applications also run in one home cell each, reached by public DNS and moved by the migration workflow like internal ones, so a release updates each application in place in its home cell and a cell failure costs its applications a short outage until the failover (sections 1.0 to 1.5, 3.1 to 3.5, 4.3, 5.2, 6.1 to 6.3) ([#130](https://github.com/onek8s/onek8s.github.io/pull/130)).
- The acceptance criteria follow: load reaches each application at its home cell, a cell loss fails over every application, and a planned migration may leave the name unresolvable for the DNS switch alone (0.3) ([#130](https://github.com/onek8s/onek8s.github.io/pull/130)).

## v4.12 - 2026-11-25

- Tenants are separated from the cells: a catalogue of one file per tenant, built by a tenant stage with a state and pipeline of its own into every cell of the tenant's zone (namespace, access, Flux configurations, vault federation, the zone gateway's tenant list), so a new application is one file whose plan touches no cell (sections 1.2, 1.5, 3.3, 6.1) ([#129](https://github.com/onek8s/onek8s.github.io/pull/129)).

## v4.11 - 2026-11-25

- An application of a zone can be moved to node pools of its own (`se2ex`, tainted `platform/pool=<namespace>`) by its namespace alone: Kubernetes' PodNodeSelector and PodTolerationRestriction admission plugins place its pods from the namespace's annotations, and a tolerations whitelist on every zone namespace keeps other pods off the pool (sections 1.2, 2.3) ([#128](https://github.com/onek8s/onek8s.github.io/pull/128)).

## v4.10 - 2026-11-09

- New page 3.6 weighs node pool upgrades - AKS's rolling surge upgrade, blue/green node pools as generations beside each other (added, retired by a taint, removed) and AKS's blue-green strategy (preview) - with pros and cons and when each is used; zone pools are named by country and generation (`se1spot`, `fi1z1`) (sections 1.2, 2.3, 3.1, 3.5, 3.6) ([#127](https://github.com/onek8s/onek8s.github.io/pull/127)).

## v4.9 - 2026-11-09

- New page 4.3 weighs a service mesh, pros and cons, and how one would meet the isolation zones: AKS's managed Istio shares one control plane and CA per cell, so only a self-managed control plane per zone keeps the zone the bulkhead; 4.1's section on the mesh moved there (sections 1.2, 4.1, 4.3) ([#126](https://github.com/onek8s/onek8s.github.io/pull/126)).

## v4.8 - 2026-11-09

- A zone's Traefik reads the `Secret`s of its own namespace and the zone's application namespaces alone, and only App Routing's gateways share a control plane, istiod, which reads every zone's `Secret`s (sections 2.3, 2.4, 4.1) ([#125](https://github.com/onek8s/onek8s.github.io/pull/125)).

  ([#109](https://github.com/onek8s/onek8s.github.io/pull/109)).
