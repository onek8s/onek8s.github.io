This page is the decision log of the design: what was decided, which options were weighed, why, and what still
needs a named human. The sections of the design stay the specification; this page says *why* they read as they do and
which choices are still provisional. What a person still has to weigh beyond the sign-offs below is in
[open questions](7.3-open-questions.md).

**How to read the tables**

| Status | Meaning |
|---|---|
| **Decided** | Justified below, reflected in the sections, no human action needed. Re-opened only by a design pull request. |
| **Decided – confirm** | The design has chosen a default, but the choice spends money, accepts a risk or binds another team, so a named role must sign it off ([human sign-offs](#human-sign-offs-still-needed)). |
| **Verify** | No decision to make; an assumption about Azure that acceptance ([acceptance criteria](../requirements/0.3-acceptance-criteria.md)) proves or disproves ([capability matrix](#azure-capability-and-verification-matrix)). |
| **Open** | Only a human can answer it (business targets, regulation, corporate IPAM). The design states the default it assumes meanwhile. |

**Criteria** used to justify a decision, in the order the platform weighs them when they conflict:

| Code | Criterion |
|---|---|
| **Sec** | Security: least privilege, smaller blast radius, defence in depth |
| **Auto** | Maximum automation: no manual steps, no human in loops that must react in minutes |
| **Std** | Industry standard, or the Azure standard offering that AKS manages and upgrades |
| **Simple** | Fewer moving parts to run, patch and reason about |
| **Cost** | Lower steady-state or failure-mode cost |
| **Port** | Portability: open standards, the same platform in another cloud ([section 1.3](../design/1.3-open-standards-and-portability.md)) |
